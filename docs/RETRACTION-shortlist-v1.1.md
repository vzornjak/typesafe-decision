# Retraction — shortlist v1.1 "validation" (2026-09-20)

**Status: RETRACTED.** This document exists so the retraction ships with the code
instead of living only in a working note. Nothing in it should be cited as
evidence of shortlist quality.

## What was originally claimed

An internal working note reported a `rank mode=shortlist` run over a frozen
16-source corpus and presented it as a validation of shortlist quality:

- decision: `selected`
- selected: 8 of 16 sources
- uncovered requirements: "0/12"
- estimated selected context: ~45,253 characters
- full corpus: ~93,752 characters
- **estimated character reduction: 51.7%**

## Why it is retracted

Three independent defects, any one of which is disqualifying:

1. **Evaluation leakage.** The `requirements` sent to Jev *were the gold
   checklist itself*. The run was therefore scored against the same list it was
   given, so "0 uncovered" is close to tautological and measures nothing about
   retrieval or selection quality.
2. **Wrong requirement count.** The real requirement count was **11**, not the
   12 stated in the note. The headline "0/12" was never the actual denominator.
3. **Undocumented non-default parameter.** The run used **`max_per_domain=4`**
   while the documented and shipped default is `max_per_domain=2`. The reported
   result is therefore not the behaviour a user gets with defaults. The stricter
   documented default demonstrably selects fewer same-domain sources — this is
   locked by the regression test
   `P0-6 / documented default max_per_domain=2 replays to the audited weaker recall`.

In addition, the character reduction was computed from extract lengths, not from
main-model token telemetry, so even a clean rerun would produce an **estimate**
rather than a measurement.

## What the number may be used for

`51.7%` may be quoted **only** as an uncontrolled *projection* of character
reduction, always with this retraction attached. It is not a measurement, not a
quality claim, and not a benchmark result.

## What would replace it

A clean re-evaluation requires, at minimum:

- requirements written independently of the gold checklist (no leakage);
- documented default parameters, or an explicit, justified deviation;
- a held-out labeled set with the labeling protocol published;
- reduction reported against real main-model input-token telemetry, not
  character estimates;
- more than one query/corpus, with variance reported.

That work is **not done**. Until it is, shortlist stays **experimental and
advisory**, and audit finding **P0-6 remains PARTIAL**: the false claim has been
retracted and the retraction is enforced by tests, but no valid replacement
evidence exists.

## Note on this public repository

The original corpus, the original working note and the original run artifacts
are internal and are **not** included here. The regression suite runs against
fully synthetic fixtures generated by `tests/generate_fixtures.py`, which
reproduce the relevant *policy property* (default `max_per_domain=2` recalls
fewer same-domain sources than `max_per_domain=4`) without redistributing any
real corpus, transcript or log.
