# Public publish checklist

Use this checklist for every public release. Do not skip a gate because a previous local audit passed.

## 1. Scope and ownership

- [ ] Work in a release copy or dedicated branch, never directly against a live installed skill.
- [ ] Confirm there is exactly one writer for the release tree.
- [ ] Treat timed-out background writers as `UNKNOWN` until cancelled or terminal.
- [ ] Record source hashes before packaging.

## 2. Privacy and licensing

- [ ] No `.env`, API key, bearer token, private key, credential, or environment value.
- [ ] No production `decisions.jsonl` or real audit-log content.
- [ ] No user conversations, agent transcripts, session/job IDs, or private benchmark corpus.
- [ ] No absolute dependency on `/var/minis`, `/Users`, or `/home/<user>`.
- [ ] Synthetic fixtures declare `origin=synthetic` and are regenerated deterministically.
- [ ] `LICENSE`, `NOTICE`, `references/official-LICENSE`, and attribution remain present.
- [ ] Project is described as unofficial; upstream trademarks do not imply endorsement.

## 3. Required gates

From the repository root:

```bash
unset TYPESAFE_API_KEY
export TYPESAFE_OFFLINE=1
export PYTHONDONTWRITEBYTECODE=1
python3 tests/run_tests.py --verbose
```

Require:

- [ ] compilation succeeds
- [ ] selftest is 25/25
- [ ] regressions are exactly 119 tests, 119 unique, 0 duplicates, 0 failures
- [ ] final gates are 2/2
- [ ] fixture integrity passes
- [ ] secret scan reports 0 hits
- [ ] absolute-path dependency scan reports 0 problems
- [ ] test log is isolated and unchanged by probes

Check deterministic fixture regeneration:

```bash
before="$(find tests/fixtures -type f -exec sha256sum {} + | sort | sha256sum)"
python3 tests/generate_fixtures.py
after="$(find tests/fixtures -type f -exec sha256sum {} + | sort | sha256sum)"
test "$before" = "$after"
```

- [ ] fixture tree is byte-identical after regeneration

## 4. Documentation truthfulness

- [ ] `README.md`, `SKILL.md`, policies, and `CHANGELOG.md` agree on version and safety posture.
- [ ] `docs/RELEASE-AUDIT.md` records exact observed results, not expectations.
- [ ] P0-6 remains `PARTIAL` until a new preregistered blind evaluation exists.
- [ ] The retracted 51.7% value is never presented as validated savings or quality evidence.
- [ ] Shortlist is described as experimental/advisory.
- [ ] No model output is described as authorization for side effects.

## 5. Git and GitHub

- [ ] Inspect `git diff --check` and the complete staged diff.
- [ ] Ensure generated bytecode and temporary files are ignored and absent.
- [ ] Commit only after all local gates pass.
- [ ] Create the GitHub repository as **public** with the intended owner and name.
- [ ] Push the reviewed commit and verify the remote URL and visibility.
- [ ] Wait for GitHub Actions to reach a terminal successful state.
- [ ] Verify the public file list in a fresh clone.
- [ ] Create a version tag/release only after CI is green.

## 6. Post-publish record

Record in the release notes:

- commit and tag
- CI run URL and status
- Python versions tested
- regression/selftest counts
- synthetic fixture aggregate hash
- P0/P1 matrix and P0-6 caveat
- known limitations and security contact path
